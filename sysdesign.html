CASE STUDY · TRY IT

Why does Stripe require a new idempotency key if the request payload changes, even if it looks like a retry?

Reusing a key with different data would indicate a different operation, not a retry. Stripe's server stores the result tied to each key and returns it unchanged on a repeat — but only for the exact same payload. That's what makes retries safe without risking a second charge on a genuinely different request.
